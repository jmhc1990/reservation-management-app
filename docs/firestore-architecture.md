# Firestore Architecture

## Overview

This document defines the Firestore database structure for the StyleSync application, including collections, fields, data types, roles, and security rules.

---

## Collections

### `users`

Stores all application users regardless of role.

| Field | Type | Description |
|---|---|---|
| `email` | String | User email address |
| `name` | String | Full name |
| `phone` | String | Phone number |
| `role` | String | `'admin'` \| `'staff'` \| `'client'` |
| `specialization` | String? | `'barber'` \| `'stylist'` \| null — only applies when `role == 'staff'` |
| `createdAt` | Timestamp | Account creation date |

> **Note:** The document ID is the Firebase Auth `uid`. It is not stored as a field inside the document.

**Example document** `/users/{uid}`:
```json
{
  "email": "john@example.com",
  "name": "John Doe",
  "phone": "+34 600 000 000",
  "role": "staff",
  "specialization": "barber",
  "createdAt": "2025-04-21T10:00:00Z"
}
```

---

### `appointments`

Stores all bookings between clients and staff members.

| Field | Type | Description |
|---|---|---|
| `client_id` | String | UID of the client |
| `staff_id` | String | UID of the assigned staff member |
| `service_id` | String | ID of the booked service |
| `start_time` | Timestamp | Exact start date and time |
| `duration` | Number | Service duration in minutes |
| `status` | String | `'confirmed'` \| `'cancelled'` \| `'completed'` \| `'no_show'` |

> **Note:** The document ID is auto-generated by Firestore.

**Example document** `/appointments/{appointmentId}`:
```json
{
  "client_id": "abc123",
  "staff_id": "xyz789",
  "service_id": "svc456",
  "start_time": "2025-04-21T11:00:00Z",
  "duration": 30,
  "status": "confirmed"
}
```

---

### `services`

Stores the service catalogue managed by the admin.

| Field | Type | Description |
|---|---|---|
| `name` | String | Service name |
| `price` | Number | Price in euros |
| `duration` | Number | Estimated duration in minutes |
| `description` | String | Service description |

> **Note:** The document ID is auto-generated by Firestore.

**Example document** `/services/{serviceId}`:
```json
{
  "name": "Classic Haircut",
  "price": 15.00,
  "duration": 30,
  "description": "Traditional haircut with scissors and razor finish."
}
```

## Roles

| Role | Description |
|---|---|
| `admin` | Full access. Manages services, staff, schedules, and business metrics. |
| `staff` | Intermediate role. Manages their own agenda only. Has a `specialization` field to distinguish between `barber` and `stylist`. |
| `client` | Can browse services, book appointments, and manage their own bookings. |

### Staff Specializations

| Specialization | Description |
|---|---|
| `barber` | Specializes in haircuts, beard grooming, and traditional barbering. |
| `stylist` | Specializes in styling, coloring, and hair treatments. |

> Both specializations share the same permissions (`staff` role). The `specialization` field is informational and used for filtering in the UI.

## Security Rules Summary

Full rules are defined in `firestore.rules`. Below is a summary per collection:

### `users`
| Operation | Who can |
|---|---|
| Read | Own user or admin |
| Create | Own user only — `role` forced to `'client'` |
| Update | Own user (cannot change `role`) or admin |
| Delete | Admin only |

### `appointments`
| Operation | Who can |
|---|---|
| Read | Client (own), staff (own), admin (all) |
| Create | Client or admin — `status` forced to `'confirmed'` |
| Update | Admin (full) or staff (own, `status` field only) |
| Delete | Admin only |

### `services`
| Operation | Who can |
|---|---|
| Read | Any authenticated user |
| Create / Update / Delete | Admin only |

---

## Implementation Notes

- The `uid` from Firebase Auth is used as the Firestore document ID for `users`. It is not stored as a field inside the document.
- The `role` field is stored as a plain string to allow direct comparison in `firestore.rules` via `get()`.
- Staff `specialization` is `null` for `admin` and `client` roles.
- New users always register with `role: 'client'`. Only an admin can promote a user to `staff` or `admin`.
